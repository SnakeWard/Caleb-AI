# V1 Phase Boundaries

This file prevents phase bleed. Codex MUST stay within the authorized phase.

## V1 - Hollow Server MVP Foundation

Allowed:

- TypeScript project setup
- Core types
- Hollow manifest
- Hollow registry
- Hollow runner
- schema validation
- Verified Return Path
- JSONL Ledger
- basic report builder
- first simple Hollows
- tests
- CLI or minimal command interface

Not allowed:

- full Role Rotation
- multi-model provider routing
- production auth
- cloud deployment
- complex UI
- 3D Thinking Mode
- unrestricted shell execution
- side-effecting Hollows without approval
- large project-specific Hollow catalog

## V1.5 - Auto Snapshot and Change Guard

Allowed:

- Snapshot Manager
- snapshot manifests
- file hashing
- rollback manager
- guard runner
- snapshot Ledger entries

## V2 - Project-Specific Hollows

Examples:

- Suno Prompt Hollow
- TropeKill Hollow
- WARCRY visual consistency Hollow
- Gemini Canvas stability Hollow
- Vendor Comparator Hollow
- Solomon's Forge pass Hollow

## V3 - Role Router and Role Rotation

Allowed later:

- Planner
- Analyst
- Critic
- Synthesizer
- complexity scoring
- loop bounds
- role traces in Ledger

## V4 - Multi-Model API Layer

Allowed later:

- provider abstraction
- GPT, Claude, Gemini, and Grok adapters if authorized
- model cost tracking
- provider fallback

## V5 - Security and Governance Hardening

Allowed later:

- signed manifests
- stronger sandboxing
- side-effect policy gates
- provenance export
- audit reports

## Future UI - 3D Thinking Mode

Allowed later:

- React Three Fiber UI
- telemetry-driven scene
- role ring visualization
- Hollow activity visualization
- Verified Return Path gate
- Ledger stack
- replay timeline
- 2D inspector

The 3D UI is a telemetry surface, not the engine. It MUST NOT be implemented until engine event streams exist or mock trace fixtures are explicitly authorized.
