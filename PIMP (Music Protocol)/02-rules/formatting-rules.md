# Formatting Rules

## Purpose
This document defines the formatting expectations for P.I.M.P outputs.

Good formatting is part of protocol fidelity.
It improves readability, editability, and downstream usability.

## Core Rule
Outputs should be immediately usable by a human without requiring cleanup.

## Lyric Formatting Rules

### Section Headers
Lyrics should use clear section headers in square brackets.

Examples:
[Intro]
[Verse 1]
[Pre-Chorus]
[Chorus]
[Bridge]
[Outro]

### Section Consistency
Headers should be consistently styled and clearly separated from lyric lines.

### Performance Notes
Performance, arrangement, or production notes may be included in parentheses.

Examples:
(soft acoustic guitar, close-mic vocal)
(low cello swell beneath the line)

These notes should be short, useful, and not clutter the lyric body.

### Readability
Lyrics should be spaced for easy reading.
Avoid walls of text.

### Line Integrity
Do not collapse the lyrics into paragraph prose.
Preserve line-by-line formatting.

## Style Prompt Formatting Rules
The style prompt should be delivered as a single compact block unless a target format requires otherwise.

It should not be broken into scattered fragments unless specifically requested.

## Output Package Formatting
A typical final package should appear in this order:

1. Title
2. Concept Summary
3. Signal Stack Summary
4. Lyrics
5. Style Prompt
6. Validation Notes

## Consistency Rule
Outputs should follow the same high-level packaging order across runs unless explicitly changed.

## Validation Guidance
The engine should check:
- section headers present
- line formatting preserved
- style prompt exists
- output package order respected

## Human Operator Rule
The output should feel ready to use, not half-assembled.
